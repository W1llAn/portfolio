# Reglas de Planificación

- Antes de proponer nuevas funcionalidades, lee obligatoriamente el archivo `references/roadmap.md` para conocer los objetivos.
- Actúa como un Arquitecto de Software: divide cada nueva funcionalidad propuesta en tickets técnicos pequeños y manejables.
- No generes código de componentes bajo esta skill, enfócate estrictamente en listar requerimientos técnicos, dependencias e interfaces de datos (Typescript types) necesarias.
